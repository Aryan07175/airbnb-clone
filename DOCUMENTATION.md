# Technical Documentation

This document provides a deep dive into the technical architecture, API design, and component structure of the Airbnb Web App Clone.

## 1. System Architecture

The application follows a decoupled client-server architecture:
- **Client**: A React-based Single Page Application (SPA) built with Next.js 14, acting as the presentation layer.
- **Server**: A RESTful API built with FastAPI (Python), responsible for business logic, data validation, and persistence.
- **Database**: A relational SQLite database managed via SQLAlchemy ORM.

### High-Level Data Flow
1. The **Next.js frontend** issues HTTP requests using the native `fetch` API to the **FastAPI backend**.
2. **FastAPI routes** validate incoming payloads using **Pydantic** models.
3. If valid, the route interacts with the **SQLite database** using **SQLAlchemy** sessions.
4. Data is returned to the frontend as serialized JSON, which is then hydrated into React components.

## 2. Frontend Architecture (Next.js)

The frontend leverages the new Next.js **App Router** (`app/` directory) for file-system-based routing.

### Core Technologies
- **Next.js 14**: React framework for routing and rendering.
- **Tailwind CSS**: Utility-first CSS framework for rapid, responsive UI styling.
- **Lucide React**: Consistent, clean SVG iconography.
- **Leaflet & React-Leaflet**: Interactive map rendering for property locations.

### Key Components
- **`ListingCard`**: Reusable component displaying a property's thumbnail carousel, title, price, and rating.
- **`Map`**: Dynamic Leaflet map instance that plots property coordinates using custom price markers.
- **`SearchModal`**: Complex multi-step modal handling location selection, date range picking, and guest counting.
- **`BookingWidget`**: Sticky sidebar component on the listing detail page that calculates total prices and manages reservation dates.

### State Management
State is largely managed at the component level using standard React hooks (`useState`, `useEffect`, `useMemo`). Global UI states (like opening/closing modals) are managed by lifting state up or using React Context where appropriate.

## 3. Backend Architecture (FastAPI)

The backend is a modular, high-performance API designed with Python type hinting.

### Core Technologies
- **FastAPI**: Asynchronous web framework for building APIs.
- **SQLAlchemy**: SQL toolkit and Object-Relational Mapper (ORM).
- **Pydantic**: Data validation and settings management using Python type annotations.
- **Uvicorn**: ASGI web server implementation.

### Directory Structure
- `main.py`: Application entry point and global middleware configuration (CORS).
- `models.py`: SQLAlchemy database models (Table schemas).
- `schemas.py`: Pydantic models for Request/Response validation.
- `database.py`: Database connection engine and session factory.
- `routers/`: Directory containing modularized API route definitions (Users, Listings, Bookings).

---

## 4. API Endpoints Reference

The backend exposes the following RESTful endpoints (Base URL: `/api`):

### Users
- `GET /users`: Fetch all users.
- `GET /users/{id}`: Fetch a specific user by ID.
- `POST /users`: Create a new user account.

### Listings
- `GET /listings`: Fetch all properties (supports query parameters for filtering).
- `GET /listings/{id}`: Fetch detailed information for a specific property.
- `POST /listings`: Create a new property listing.
- `DELETE /listings/{id}`: Delete an owned property.

### Bookings (Reservations)
- `GET /bookings`: Fetch all bookings (for the current user).
- `POST /bookings`: Create a new reservation.
- `DELETE /bookings/{id}`: Cancel a reservation.

### Reviews
- `GET /reviews/listing/{listing_id}`: Fetch all reviews for a property.
- `POST /reviews`: Submit a new review.

*(Note: Interactive API documentation is automatically generated by FastAPI and available at `/docs` on the live backend server).*

## 5. Deployment Infrastructure

The application is deployed across two specialized cloud providers:

### Frontend Hosting: Vercel
- **Why Vercel?** Vercel is the creator of Next.js and provides zero-config deployments, edge caching, and global CDN distribution.
- **Configuration**: The `NEXT_PUBLIC_API_URL` environment variable is injected during the build step to point the client-side fetches to the live backend.

### Backend Hosting: Render
- **Why Render?** Render natively supports Python web services and provides a simple Blueprint (`render.yaml`) configuration system.
- **Database Persistence**: The SQLite database (`airbnb.db`) is stored locally on the Render instance. *Note: On the free tier, the instance filesystem is ephemeral. A startup script (`seed.py`) is used to populate dummy data upon instance spin-up.*
